# zero-bridge-desktop — Install & Security

## Install (Linux)

### AppImage (recommended, no install)

```bash
chmod +x zero-bridge-<version>.AppImage
./zero-bridge-<version>.AppImage
```

### Debian/Ubuntu (.deb)

```bash
sudo apt install ./zero-bridge-desktop_<version>_amd64.deb
# then run from menu or:
zero-bridge-desktop
```

## How it works

The desktop app starts the **zero-bridge** Go binary as a sidecar on a local loopback port (or Unix socket when S21 lands). The bridge spawns the ACP agent (`zero acp` or `acpfake` for testing). The UI is served by the bridge at `http://127.0.0.1:<port>/`.

## Token & Security

- A **per-launch token** is generated by the Electron main process and written to a `0600` file in a `0700` directory (`$XDG_RUNTIME_DIR/zb-<uuid>/token.txt` or `$TMPDIR/zb-<uuid>/token.txt`).
- The token is passed to the bridge via `--token-file`. It never appears in argv, logs, URL, or the renderer process.
- The bridge enforces: loopback-only bind, Host/Origin validation, no CORS, strict CSP.
- Native notifications for permission requests show **only the tool title** (text-only, sanitized). Agent output is never shown in notifications.
